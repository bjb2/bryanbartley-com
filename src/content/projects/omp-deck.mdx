You open the app. Sessions on the left, an active chat in the middle,
an inspector on the right. Every tool call streams into a typed
renderer: file reads, edits, bash, web search, sub-agents, browser
automation, image generation. Hit Shift+Tab and the session flips into
plan mode. The agent investigates with read-only tools, drafts a plan,
surfaces it inline for your approval, then executes with full tools
restored once you say go. Type `/task add` and a card lands on the
kanban; the same card refreshes in every open tab because the server
broadcasts the change. Schedule a routine for weekday mornings, or
build one on a visual node canvas if YAML isn't your thing. DM the
Telegram bridge from your phone and the agent answers there.

The audience is anyone driving an omp coding agent who wants a calmer
surface than a terminal for long sessions, plus the workflow
scaffolding around it. A kanban for what the agent is doing. An inbox
for what you want next. A knowledge base over your local markdown the
agent can read as it works. A plan-mode loop so the agent can propose
before it executes.

## How it stays honest

omp-deck doesn't reimplement the agent. It embeds the same omp SDK
in-process and shares the OAuth and API-key store with the terminal
CLI. The chat surface stays at TUI parity by construction. You can
run both side by side and the agent doesn't know the difference.

Plan mode, todo-panel live-sync, queued-prompt editing, and `kb://`
resolution from inside agent sessions are all built on top of the
same SDK surfaces the TUI uses, never a parallel reimplementation.
When the SDK ships something new, the deck picks it up rather than
forking.

A Bun and Hono server holds the REST and WebSocket layer; a Vite and
React frontend consumes the stream. No client-side polling. The whole
thing is one process that cold-starts in under a second.

## What's in it

The chat is the centerpiece: multi-session, per-tool renderers,
hashline diffs, thinking blocks, cost rollups, paste-and-drop images,
queued prompts you can edit or cancel mid-stream, composer history
recall per workspace, and Shift+Tab plan mode with inline Approve /
Reject / Edit cards.

The kanban has stable `T-N` IDs, drag-and-drop, configurable columns,
live broadcasts, and image paste straight into task bodies. The inbox
sits alongside it for quick capture and promote-to-task. Routines
author as YAML or in a visual React Flow canvas that round-trips
through spec edits without losing layout; each run is observable
step-by-step, with stdout, JSON output, cost, and replay surfaced
inline.

The knowledge base sits over `~/kb` with a markdown viewer, wikilink
resolution, full-text search, and an Obsidian-style force-directed
graph. `kb://` URLs from agent sessions resolve through the same root,
so the agent can read your notes by reference without copy-paste. An
omp-native skills catalog spans every provider the SDK loads; five
starter skills (handoff, diagnose, zoom-out, prototype, grill-me)
auto-install on first boot.

A reliability stack runs underneath: heartbeat frames, a
restart-on-crash supervisor, a connection indicator in the header, and
a notification service that surfaces routine failures and
agent-shipped tasks as OS notifications. A bundled maintenance-gate
extension nudges the agent to file insights into your org folders at
turn end. An orientation panel makes the session prelude, `/start`
command, and gate behavior editable from the UI without touching
server source. Three themes (paper, slate, horizon), FOUC-free. A
Telegram bridge supervised by the deck so the agent stays reachable
from the couch.

## Hosting

A single Bun process, loopback-only by default. The intended deployment
is Tailscale Serve or an SSH tunnel. The deck ships without an auth
layer because anything stronger than "loopback plus your network's
edge" was outside the scope of the build. Cross-platform CI runs the
full gate matrix on Linux, macOS, and Windows on every push; the
Dockerfile (Debian-slim, glibc) boots end-to-end on Linux, and bash /
cmd launchers ship for all three OSes. MIT licensed, designed to be
cloned and run from your own machine alongside an omp CLI you already
use.
